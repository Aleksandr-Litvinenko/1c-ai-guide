# Как выбрать AI-стек для 1С

Не начинайте с названия модели или MCP-сервера. Сначала определите поверхность доступа.

## 1. Что должен делать AI

| Задача | Нужные данные | Рекомендуемая поверхность |
|---|---|---|
| Писать или проверять BSL | Исходники и справка | Выгрузка конфигурации + Agent Skills + анализатор |
| Понимать структуру конфигурации | Метаданные, иногда исходники | MCP по выгрузке или read-only доступ к метаданным |
| Запускать сборку и тесты | Локальная среда разработки | Управляемые CLI/EDT tools без бизнес-данных |
| Строить отчёты | Ограниченный набор данных | Read-only OData или специальный HTTP API |
| Создавать документы | Справочники и документы | Отдельный write gateway с dry-run и подтверждением |
| Работать с Bitrix24 | REST API конкретного портала | Docs MCP + runtime-коннектор с минимальными scope |

## 2. Где находятся данные

- **Выгрузка XML/EDT** — лучший старт для разработки и code review.
- **Тестовая база** — безопасный следующий шаг для интеграционных сценариев.
- **Рабочая база** — только после проверки на тестовой копии.
- **Облачная 1С** — обычно удобнее использовать опубликованный провайдером OData.
- **Закрытый контур** — рассматривайте локальную LLM и шлюз без внешней передачи данных.

## 3. Какой уровень риска допустим

| Уровень | Разрешения | Пример |
|---|---|---|
| Низкий | Только локальные исходники | AI объясняет модуль или предлагает тест |
| Средний | Чтение тестовой базы | AI строит сверочный отчёт |
| Повышенный | Чтение production | AI анализирует дебиторку по allowlist |
| Высокий | Запись production | AI готовит документ после preview и подтверждения |

Если сценарий можно решить на более низком уровне, не повышайте доступ.

## 4. Минимальный pilot

1. Выберите одну измеримую задачу.
2. Подготовьте 10–30 тестовых примеров.
3. Зафиксируйте правильные ответы или результат текущего процесса.
4. Запустите AI в режиме чтения.
5. Измерьте точность, время, стоимость и число ручных исправлений.
6. Только после этого расширяйте поверхность доступа.

## 5. Критерии выбора инструмента

- открытая лицензия;
- понятный data flow;
- отдельные режимы чтения и записи;
- документация установки;
- минимальный набор зависимостей;
- журналирование;
- активное сопровождение;
- возможность ограничить tools и объекты;
- воспроизводимый demo или тесты.

Не выбирайте проект только по числу звёзд.
