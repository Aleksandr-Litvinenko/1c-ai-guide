# Read-only бизнес-аудит 1С

Цель: дать AI возможность находить управленческие отклонения без изменения данных.

## Подходящие первые контроли

- дебиторы с просроченной оплатой;
- отрицательные остатки;
- резкий рост закупочной цены;
- продажи ниже себестоимости;
- дубли контрагентов;
- документы без ответственного или договора;
- аномальное изменение выручки по неделям;
- расхождения между задачами Bitrix24 и учётом времени.

## Безопасная схема

```text
отдельный read-only пользователь
  → ограниченный состав OData/API
  → локальный MCP или шлюз
  → allowlist аналитических tools
  → AI-клиент
```

## Порядок пилота

1. Создайте тестовую копию базы и обезличьте данные.
2. Выберите один контроль и короткий период.
3. Сохраните эталонный отчёт 1С.
4. Дайте AI доступ только к необходимым сущностям.
5. Сравните суммы, количество строк и пограничные случаи.
6. Зафиксируйте запрос, инструменты и версию конфигурации.
7. Добавьте понятные статусы: красный, жёлтый, зелёный.
8. Перед production повторите тест на свежей копии.

## Правила результата

AI должен возвращать не только вывод, но и проверяемую основу:

- период;
- организация;
- использованные сущности;
- число обработанных записей;
- критерий отклонения;
- ссылки или идентификаторы объектов;
- ограничение и степень уверенности.

## Чего не делать

- Не использовать административную учётную запись.
- Не открывать весь состав OData «на всякий случай».
- Не отправлять персональные данные во внешнюю модель без правового основания.
- Не принимать текстовый вывод AI без сверки контрольных сумм.
- Не включать запись в рамках read-only пилота.
