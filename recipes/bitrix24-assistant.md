# AI-ассистент для Bitrix24

Разделяйте знание API и доступ к порталу.

## Два слоя

### 1. Документация

[Официальный Bitrix24 MCP REST documentation](https://github.com/bitrix24/mcp-rest-doc) даёт агенту актуальный контекст по методам и параметрам API.

Этот слой не должен хранить webhook конкретного портала.

### 2. Runtime

Runtime-коннектор выполняет разрешённые действия в конкретном Bitrix24:

- читает задачи;
- проверяет заполнение результатов;
- собирает часы;
- читает CRM-компании и сделки;
- создаёт действия только при явном разрешении.

Варианты для изучения: [bitrix24-mcp](https://github.com/kartochka/bitrix24-mcp), [OpenIntegrations](https://github.com/Bayselonarrend/OpenIntegrations), [официальный шаблон MCP](https://github.com/bitrix24/templates-mcp).

## Первый безопасный сценарий

Проверка закрытых задач за месяц:

1. Прочитать задачи со статусом «завершена».
2. Проверить списанное время.
3. Проверить наличие результата и даты выполнения.
4. Проверить привязку к CRM-компании или сделке.
5. Сформировать отчёт без изменения портала.

## Минимальные правила

- отдельный webhook или OAuth-приложение;
- минимальный набор scope;
- секреты только в переменных окружения или secret manager;
- пагинация и соблюдение rate limits;
- журналирование методов без значений секретов;
- запись отключена по умолчанию;
- все изменения проходят preview и подтверждение.

## Не публикуйте

- URL входящего webhook;
- OAuth client secret;
- выгрузки с именами сотрудников и клиентов;
- полные payload запросов из production;
- cookie и session tokens.
